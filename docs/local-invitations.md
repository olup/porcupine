# Connect an MCP client with a local invitation

Enable `PORCUPINE_LOCAL_INVITATIONS=true` alongside `PORCUPINE_OAUTH_ISSUER` in the OAuth deployment. Set the issuer to the canonical public HTTPS origin. Select one interactive login method per deployment: local invitations or upstream OIDC. The machine client credentials flow remains available in both modes.

1. [Register the downstream OAuth client](mcp-interactive-oauth.md#register-the-downstream-client) with its exact callback, S256 PKCE, the two read scopes, and the intended projects. Configure its client ID in ChatGPT, Claude or another MCP client.
2. Ask your admin agent to call `create-local-invitation` with the project ID. The HTTP equivalent is `POST /api/v1/projects/{id}/invitations` with an instance-admin API token and no body. The response contains the invitation ID, project ID, expiration and a code returned once. Store the ID for revocation. Share the code privately with the invited person. Anyone holding it can redeem it.
3. The invited person starts **Connect** in the MCP client at the issuer’s `/mcp` endpoint and pastes the code into the Porcupine browser page. The consent page shows the registered client, redirect address, scopes and project. Approving consumes the code in the same transaction that creates the authorization grant. Opening the form, reviewing access or denying leaves the invitation available until expiry.
4. The authorized client can read events and metadata for the invited project. The invitation expires after 24 hours. After redemption, the existing OAuth access-token and grant lifetimes apply independently. If the connection expires or is revoked, a new invitation is needed.
5. To cancel an unused invitation or disconnect its client, call `revoke-local-invitation` or `DELETE /api/v1/invitations/{id}` as instance admin. Revocation rejects further MCP access and refreshes. A supported backup restore also invalidates outstanding invitations and interactive grants.

Agents use `porcupine_docs` to discover the installed operations and `porcupine_call` to invoke them. Use a machine MCP credential with instance-admin permission for invitation management. Invited users receive only project-scoped read permissions. The server stores a hash of the code and never uses it as an API bearer token.
