What it does

Capture

Keep a supported PostHog SDK, send Segment events, or POST your own JSON. A cookieless browser profile counts daily visitors without storing anything in the browser.

Query

Agents look up event names and properties, then run project-scoped DuckDB SQL over MCP, HTTP or the CLI. Funnels and retention are joins and window functions.

Deliver

Send each new event to a webhook, alone or in batches. Schedule a SQL query and have Porcupine write its results to your S3 bucket.

Import

Bring PostHog exports, Segment files or native JSONL with one CLI command. Imports resume after interruption and keep the original event times.

Share

Invite your team to projects. Each person approves their own MCP or CLI connection, and HTTP, CLI and MCP enforce the same permissions.

Store

DuckDB and DuckLake run inside the server. A single process with SQLite runs a whole instance, with analytical files on local disk or a private S3 bucket.

Already on PostHog?

Point your SDK at Porcupine. Porcupine is tested against pinned posthog-js and posthog-node versions. Compatibility

posthog.init(projectIngestionKey, {
  ...cookielessProfile,
  api_host: 'https://analytics.example.com',
  opt_out_useragent_filter: false
})
posthog.capture('signup_completed', { plan: 'team' })

Why it exists

It works with PostHog and Segment clients. Headless means it ships with no UI at all. Once it’s installed, an agent or a human can manage it and query it through MCP or the CLI.

I wanted a lightweight product analytics tool I could self-host. Then I realised no one on my team ever opens the PostHog UI. Our local agents already manage everything and run the queries.

PostHog, OpenPanel and Pug were big inspirations. I wanted direct SQL queries, pipelines that send data to other systems, and the option to offload older data to S3, all in something light enough to host myself.

This text is human. The agent did the rest.
